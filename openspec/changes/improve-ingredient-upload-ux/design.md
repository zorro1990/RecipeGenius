## Layout Blueprint

### Upload (Idle)
- **Visible elements**: 上传面板、格式/大小提示、隐私说明。
- **Hidden/secondary**: 「功能特点」折叠为单行链接 `了解更多功能`，点击后在侧滑中展示原说明。
- **Goal**: 用户一眼定位上传动作，辅助提示不占主视觉。

### Recognition Success
- **Summary bar**（置顶卡片）：
  - 左侧显示 `AI识别结果` 标题 + 置信度徽章（绿色≥80%，黄色60-79%，红色<60%）。
  - 右侧为 `展开识别说明` 按钮，默认折叠文字描述；展开后覆盖整段说明，可再次收起。
- **Main grid**（桌面双列，移动端堆叠）：
  - **左列：食材列表** 可编辑行 + 添加输入框，新增项标记 `人工补充`。
  - **右列：分类筛选** 标签可点击，高亮当前分类并滚动定位到对应列表项；下方按钮 `查看推荐` 打开建议抽屉。
- **Suggestion drawer**（底部浮层）：
  - 标题 `来自AI的建议`，列出可多选的建议食材；勾选后按钮文案 `添加所选食材`。
  - 添加成功后刷新左列列表并携带 `人工补充` 标签。
- **Alerts**：低置信度时保留提醒；抽屉内补充一条提示说明建议来源。

### Confirmation
- Top 提示保留 `食材已确认` 与 `重新识别` 次要按钮。
- 移除独立的「立即生成菜谱」按钮，改为引导用户关注页面底部唯一 CTA。
- 成功消息用轻量文本，避免与底部 CTA 抢夺注意力。

## CTA State Spec

Target component：页面底部的渐变卡片按钮。

| 状态 | 触发条件 | 按钮文案 | 样式与行为 | 辅助文案 |
| --- | --- | --- | --- | --- |
| idle-ready | 已确认至少 1 条食材且未在请求中 | `生成我的专属菜谱` | 主按钮启用，展示 ✨ 图标 | `已添加 X 种食材，点击生成` |
| idle-disabled | 尚未确认食材 | `请先确认食材` | 按钮禁用，使用浅色边框 | `还没有食材，请上传或手动添加` |
| loading | 请求进行中 | `AI 正在创建菜谱...` | 按钮显示 `Loader` 动画，禁用点击 | 底部保留 `预计约 1 分钟` 提示，无额外按钮 |
| success | 请求完成并跳转至菜谱页前 | `查看菜谱详情`（在跳转发生前短暂显示） | 若保持在页内则按钮带亮眼边框，点击跳转 | `生成完成，可继续调整食材` |
| failure | 请求失败 | `重新尝试生成` | 按钮恢复可点击，左侧警示图标；错误信息展示在按钮上方警告框 | 警告框说明失败原因及建议操作 |

说明：
- 按钮唯一性：生成流程中不再出现顶部或其他位置的生成按钮，使用相同 CTA 引导。
- 状态切换：`idle-ready → loading → success/failure`。从 `success` 返回后若用户修改食材，则回到 `idle-ready`。
- Accessibility：loading 状态加 `aria-busy`，禁用时加 `aria-disabled`，并通过 `aria-live="polite"` 宣告状态变化。

## Mobile Considerations
- Summary bar与分类筛选改为纵向堆叠，分类标签使用横向滚动列表示例。
- 建议抽屉占据 80% 屏幕高度，保留滑动关闭手势。
- 底部 CTA 卡片保留固定间距，避免被键盘遮挡；在键盘开启时允许卡片浮起。
