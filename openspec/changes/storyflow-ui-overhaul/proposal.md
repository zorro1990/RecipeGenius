## Why
现有界面停留在卡片堆砌与表格式信息呈现，缺少完整的故事叙事和过程反馈：
- 生成流程只提供静态状态文本，用户难以预期剩余时间与系统行为。
- 结果页信息密度高但缺乏视觉聚焦，菜谱卖点、健康信息与匹配结果被淹没。
- 偏好设置与确认食材仍是单页表单，缺少分步引导与即时预览，体验割裂。
- 健康建议等二级信息没有交互结构，难以在移动端或高信息场景下迅速扫描。

为了让 RecipeGenius 在体验上向旗舰产品跃迁，需要重塑生成故事流、分步向导、结果展示及健康建议布局。

## What Changes
- 将「生成菜谱」流程改造成故事流：点击 CTA 后进入全屏遮罩，展示 Skeleton、进度时间轴、菜系匹配回馈，完成后顺滑过渡到结果页英雄卡片。
- 重构结果页顶部，采用 Hero 模块整合菜谱封面、菜系匹配、营养评分及 CTA，并为关键指标加入动画过渡。
- 将偏好设置拆分成 3 步 Wizard（基础参数 -> 饮食偏好 -> 健康/菜系），每步支持实时预览和校验，并引入菜系推荐/切换提示。
- 健康建议区改为卡片 Tab/Pill 切换模式，按提示类型（风险、益处、重点、建议）配合颜色语义与图标体系。
- 建立统一的 Skeleton、Hero、Storyflow Stepper 等 UI 组件，确保全局视觉一致。

## Impact
- Affected specs: recipe-generation, ingredient-collection (新增故事流与向导要求)
- Affected code：
  - `app/ingredients` 页面结构与状态管理
  - `app/recipe` 结果页组件与渲染逻辑
  - 共享 UI 组件库（Wizard、Stepper、Skeleton、Hero、Tabs）
  - 状态流（生成状态、菜系匹配反馈、健康建议数据）

## Acceptance Criteria
- 生成过程中用户能看到分段 Skeleton 动效与进度标记，并在 2 次重试内明确获知菜系匹配结果。
- 偏好设置 Wizard 在任一步均可返回编辑，上一步的选择实时影响右侧预览卡片，且菜系建议能根据失败重试结果更新。
- 结果页 hero 卡片在 400ms 内完成关键指标的入场动画，菜谱数据、菜系匹配及健康建议按模块分区呈现。
- 健康建议区提供标签式切换，默认显示最关键的风险/益处，并在移动端保持良好可读性。
